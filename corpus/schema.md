# 语料字段定义

一行一条 JSON（JSONL），UTF-8。

## 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识，形如 `spell:光射线` / `rule:容量` |
| `kind` | enum | `spell` 咒语 / `rule` 规则 / `rune` 魔文 / `meta` 元信息 |
| `chapter` | string | 章节，形如 `第22章 光射线` |
| `speaker` | string | `叙述` 或角色名（如 `墨砚秋`、`星瑕`） |
| `viewpoint` | enum | `全知` / `角色` / `拟人修辞` |
| `layer` | enum | `真实` / `模拟` / `设定` |
| `quote` | string | 逐字引文，≤40 字；超长用 `…` 截断，但不得改动字词 |
| `fields` | object | 见下 |

## `fields` 内每一项

```json
"环数": { "value": 2, "status": "原文" }
"魔文数": { "value": 4, "status": "原文" }
"元素": { "value": "光", "status": "原文" }
"类别": { "value": "攻击", "status": "推断", "basis": "…" }
"穿盾": { "value": null, "status": "无" }
```

`status` 取值：`原文` / `推断`（必须带 `basis`）/ `无` / `悬置`。

## `layer` 的含义

- `真实`：角色在真实世界施放或学习
- `模拟`：对战空间 / 模拟对战装置内的系统技能，有技能栏、读条、血条
- `设定`：叙述者交代的规则，不对应具体一次施法

## `viewpoint` 的含义

- `全知`：第三人称叙述者
- `角色`：角色视角内的观察
- `拟人修辞`：叙述者把非人对象当人说话（如“一环魔法表示大姐你别闹了”）

## 硬约束

1. `quote` 必须能在原文中逐字检索到。
2. `status: 原文` 的数值，必须来自 `quote` 本身或紧邻上下文，不得跨段合并。
3. 疑问句、推测句不得标 `原文` 用于设定结论。

## 附：`templates.jsonl`

与 `corpus.jsonl` 分开存放，只记录**模板实例**，不重复原文。

| 字段 | 说明 |
|---|---|
| `template` | 模板名，目前只有 `projectile` |
| `spell` | 咒语名，需与 `corpus.jsonl` 的 `spell:<名字>` 对应 |
| `element` | 元素 |
| `declared_runes` | 原文声明的魔文总数 |
| `create` | 元素实体段的魔文数组；`null` 表示原文未给 |
| `create_source` | `原文` / `推断` / `unknown` |
| `emit` | 发射段的魔文数组 |
| `corpus_id` | 反向指向 `corpus.jsonl` 的 `id` |

`create: null` 是合法的，表示“原文没写”，不是缺字段。

**`emit` 的两个 `发射` 是两个不同魔文**，同名是因为原文只给了语义标签（“新的两个魔文，意思是发射”），
没给各自独立的名称。编译器靠位置区分它们。
