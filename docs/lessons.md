# 经验与教训

这份文档记录本项目在二十余轮评审中沉淀下来的方法、反复犯的错、以及引文纪律。
它比任何设计文档都更可复用：换一个作品、换一套设定，这里的东西仍然成立。

---

## 一、方法：从语料到原型

顺序不能颠倒。

1. **语料审计优先于设计。** 先把原文里可证的事实挖出来，再谈建模。跳过这一步，后面全是在猜测上盖楼。
2. **每条结论四分类**：`原文` / `推断` / `设计选择` / `悬置`。四类缺一，结论就会漂移成“看起来像事实的猜测”。
3. **说话者与视角过滤。** 同一句话，叙述者说的、老师说的、学生猜的、疑问句、心理活动，可靠性差三个量级。设定类结论只收 `叙述` 与 `可靠角色陈述`。
4. **引文逐字校验，工具化。** `tools/verify_quotes.py` 对每条引文做章节内子串匹配，不通过即非零退出。这一步抓出过真错误（章节标错），也防止了文档漂移。
5. **可证伪原型。** 代码不是“演示”，是“断言”。每条模板假设都要有一条“若出现 X 则假设死”的测试。

## 二、反复犯的六种错

这不是清单，是模式识别。同一个模式会换着皮肤反复出现。

### 1. 伪量化

给主观判断套上数字，让它看起来可验证。

- 反例：七层各拍一个百分比然后取平均；`stab >= .95` 没有任何来源。
- 修法：要么给“完成判据已满足 x/y”，要么列开放问题清单。**分母不存在时，任何百分比都是伪造。**

### 2. 假二分

遇到难以立即解决的问题，抛一个二选一，然后选坏的那端。

- 反例：“反馈就掉出可判定区，只能采样”；“不满射就只能采样”；“要么任意高阶，要么钉死四类”。
- 修法：先问“中间地带是什么”。有限状态等价、翻译验证、有界复合，都是被这类二分抹掉的第三选项。
- 这个错在项目里犯了至少三次，是本项目最高频的思维缺陷。

### 3. 用后果支撑命题

“如果按这个建模，后果很严重，所以这个命题成立。”

- 反例：用“环是反馈就会不可判定”来论证“环不是反馈”。
- 修法：只有文本证据算数。后果可以作为**动机**，不能作为**论据**。

### 4. 把抽象相似当结构同构

两个东西形状像，就认为机制相同。

- 反例：`OoO 窗口 = 环容量`。ROB 溢出是性能损失，环溢出是正确性损失——**失败模式不同类**，类比当场失效。
- 修法：类比必须过一遍“失败时发生什么”。失败模式不同，就不是同一种结构。

### 5. 用缺失当反证

“没找到”被写成“不存在”。

- 反例：因为没见到元素防御，就断言“防御是通用无元素的”。
- 修法：区分 **(a) 检索确无**（词表内零命中）与 **(b) 逻辑不可推断**（未写 ≠ 没有，只能悬置）。缺失清单必须分类，否则从证据退化成猜测。

### 6. 事后合理化

先有结论，再补规则让它成立。

- 反例：为了让“强光术”落进分类，临时造一条“按主作用分类”的判据。
- 修法：判据必须先于实例。若判据是为了容纳某个特例才诞生，它就不是规律，是定义。

## 三、引文纪律

| 规则 | 说明 |
|---|---|
| 逐字 | 不改字词，截断用 `……`，单条 ≤ 40 字 |
| 带章节 | 每条引文必须能定位到章 |
| 带说话者 | 叙述 / 角色名 |
| 带视角 | 全知 / 角色 / 拟人修辞 |
| 降级 | 疑问句、推测句、心理活动不得用于设定结论 |
| 分层 | 模拟层（技能栏、读条、血条）≠ 真实层，不得互相外推 |

**“词表内零命中” ≠ “文本没有”。** 前者是检索结果，后者是全称判断。写前者，不写后者。

---

## 四、设计决策的记录格式

每一项必须写全四栏，少一栏就不合格：

| 栏 | 内容 |
|---|---|
| 结论 | 一句话 |
| 类型 | 原文 / 推断 / 设计选择 / 悬置 |
| 依据 | 引文，或推断的推理链 |
| 翻案条件 | 出现什么就回滚 |

**“翻案条件”是最重要的一栏。** 没有翻案条件的结论，等于不可证伪的教条。

## 五、什么算证据

可靠性排序（高 → 低）：

```
叙述者设定陈述
  > 权威角色陈述（教师、长辈）
  > 普通角色陈述
  > 角色推测（“应该也”“大概”）
  > 疑问句
  > 心理活动
```

三条硬规则：

1. **单一实例不构成规律。** 一个咒语有结构，不代表一类咒语有结构。
2. **模拟层不进真实模型。** 有技能栏和血条的东西，是系统实现，不是世界规则。
3. **作者意图不是证据。** “作者简化了”是猜测，不是可观测规则。

## 六、这次真正做出来的东西

不是语言，是三样：

1. **44 条可逐字校验的引文**，覆盖 25 个咒语。
2. **一张四分类决议表**，把“能形式化”与“不能形式化”分开。
3. **24 条被撤回的错误主张**——每一条如果没被证伪，都会变成代码里的 bug。

第 3 项常被低估。设计阶段最有价值的产出，往往不是“造出了什么”，而是“知道什么不能造”。
