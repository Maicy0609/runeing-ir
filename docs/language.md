# 魔法源语言参考

这是 `runeing` 的源语言。读者照着本文即可写出咒语，编译器按本文描述给出结果。

> **符号一律 ASCII。** 标识符用中文，因为它们是原文术语（魔文名、元素名）；
> 语法符号只用 `->`、`*`、`:`、`=`、`#`。

---

## 1. 快速开始

新建 `my.rune`：

```
光射线 : 光 = 发光 -> 点 -> 发射 -> 发射
```

编译：

```bash
python3 examples/compile.py my.rune
```

输出：

```
[解析] 咒语 光射线，4 个魔文
[信息] C_OK: 容量 4/10：常态
[信息] C_ELEMENT: 元素 光：有实例
[IR] element=光 form=projectile work=4
     apply: (发光+点) |> (发射+发射)
[求值] Value(element='光', form='projectile', work=4, pipeline=('发光+点', '发射+发射'))
```

四行分别对应四个阶段：**解析 -> 检查 -> 降级 -> 求值**。

## 2. 语法

### 2.1 形式

```
名字 : 元素 = 魔文 -> 魔文 -> ...
```

| 部分 | 说明 |
|---|---|
| `名字` | 咒语名，不含空格、`:`、`=`、`#` |
| `元素` | 光 / 冰 / 火 / 金 / 风 / 木 / 水 / 土 |
| `->` | 连笔方向：前一个魔文的末尾连到下一个魔文的开头 |
| `魔文 * N` | 该魔文重复 N 次（N 为正整数） |

### 2.2 为什么是箭头

第 16 章原文：

> 从一个魔文的**末尾**连接另一个魔文的**开头**，将它们连接成一个整体

`->` 就是这句话的形状。不用括号、不用分号，因为施法本来就是一条有向序列。

为什么不用单个 `>`：`发光 > 点 > 发射` 会被读成“大于”，`->` 没有这个歧义，
也是 Haskell / Rust 等语言的箭头惯例。

### 2.3 注释与空行

```
# 这是注释
光射线 : 光 = 发光 -> 点 -> 发射 -> 发射
```

`#` 之后整行忽略。一个文件只放一个咒语。

### 2.4 重复

```
旋转阵 : 光 = 旋转 * 11
```

等价于写 11 个 `旋转`。`* 0` 或负数会报 `ParseError`。

### 2.5 源码里没有连笔

连笔是 (魔文对 × 魔女) 的私有表（第 17 章：每一位魔女所使用的连笔也与别的魔女不同）。
所以它不属于源码，由施法者补。源码只描述**哪些魔文、什么顺序**。

## 3. 编译器做什么

| 阶段 | 输入 | 输出 | 失败时 |
|---|---|---|---|
| 解析 | 文本 | `SpellSource{name, element, runes}` | `ParseError` |
| 检查 | `SpellSource` | `Diagnostic` 列表 | 有“错误”则终止 |
| 降级 | `SpellSource` | `IR{kind, element, create, emit}` | —— |
| 求值 | `IR` | `Value{element, form}` | —— |

### 3.1 容量判定

容量分两层，别混淆：

| 层 | 规则 | 用途 |
|---|---|---|
| 单调判定 | `n ≤ 10` → 常态 | 10 是“容纳”上界，小于它必然在常态内 |
| 采样判定 | 10 → 常态；13 → 一秒后崩溃；15 → 失败；其余 → 未知 | 只认原文给出的点 |

11、12、14 **没有采样**，所以只给警告 `W_CAPACITY`，不判错。

| 魔文数 | 结论 | 依据 |
|---|---|---|
| ≤ 10 | 常态 | 第 44 章“我平时也就容纳十个魔文”（上界） |
| 13 | 可成型，约一秒后崩溃 | 第 58 章实测 |
| 15 | 失败 | 第 44 章“十五个魔文根本稳定不住” |
| 11 / 12 / 14 | 无法判定（警告） | 未采样，不内插 |

### 3.2 元素判定

| 状态 | 元素 | 结果 |
|---|---|---|
| 有实例 | 光 冰 火 金 风 木 | 通过 |
| 仅提及 | 水 土 | 警告 |
| 未出现 | 雷 暗 | 错误 |

### 3.3 结构识别

4 个魔文且后两位是 `发射` 时，识别为投射模板：

```
Projectile<E> = create_E(2) + emit(2)
```

IR 用 `Apply(emit, create)` 表达「emit 作用于 create」，不是两个并列字段。

其余形状降级为 `opaque`，只保留魔文序列，不做结构判断。**`opaque` 表示结构未识别，不等于无效果。**

两种形态的求值差异：

| 咒语 | IR | 求值 |
|---|---|---|
| 光射线 | `form=projectile`，`apply=(发光+点) \|> (发射+发射)` | `pipeline=('发光+点','发射+发射')` |
| 闪光术 | `form=opaque`，`apply=None` | `pipeline=()` |

`pipeline` 非空说明经过 emit 段，空说明没有。这是「有 emit」与「无 emit」在求值结果里的可追溯差异。

## 4. 诊断码

| 码 | 级别 | 含义 |
|---|---|---|
| `C_OK` | 信息 | 容量在常态范围内 |
| `C_ELEMENT` | 信息 | 元素有实例 |
| `W_CAPACITY` | 警告 | 容量处于边缘或未采样 |
| `W_ELEMENT` | 警告 | 元素仅一句“同理”提及 |
| `E_CAPACITY` | 错误 | 容量超限，无法稳定成型 |
| `E_ELEMENT` | 错误 | 元素在原文中未出现 |

有 `E_` 前缀时，编译器终止，不生成 IR，退出码 1。

## 5. 示例

### 5.1 成功：投射

```
光射线 : 光 = 发光 -> 点 -> 发射 -> 发射
```

```
[解析] 咒语 光射线，4 个魔文
[信息] C_OK: 容量 4/10：常态
[信息] C_ELEMENT: 元素 光：有实例
[IR] element=光 form=projectile work=4
     apply: (发光+点) |> (发射+发射)
[求值] Value(element='光', form='projectile', work=4, pipeline=('发光+点', '发射+发射'))
```

### 5.2 成功：无 emit

`examples/flash.rune`

```
闪光术 : 光 = 发光 -> 点
```

```
[解析] 咒语 闪光术，2 个魔文
[信息] C_OK: 容量 2/10：常态
[信息] C_ELEMENT: 元素 光：有实例
[IR] element=光 form=opaque work=2
[求值] Value(element='光', form='opaque', work=2, pipeline=())
```

两个咒语元素相同、都是光系，求值却不同——因为一个有 emit 段，一个没有。

### 5.3 容量超限

```
巨型光球 : 光 = 发光 -> 点 -> 发射 -> 发射 -> 旋转 * 11
```

```
[解析] 咒语 巨型光球，15 个魔文
[错误] E_CAPACITY: 容量 15：十五个魔文根本稳定不住
[信息] C_ELEMENT: 元素 光：有实例
[终止] 编译失败，不生成 IR
```

### 5.4 元素不存在

```

```

```
[解析] 咒语 雷击，4 个魔文
[信息] C_OK: 容量 4/10：常态
[错误] E_ELEMENT: 元素 雷：原文未出现

```

## 6. 限制

| 限制 | 原因 |
|---|---|
| 只支持一环 | 二环只有五彩光球一个样本，且内环数出自疑问句 |
| 不支持连笔语法 | 连笔是私有的，不是源码的一部分 |
| 只识别投射模板 | 其余结构降级为 `generic`，不做语义判断 |
| 求值只到 `(元素, 形态)` | “发射”没有可计算的定义 |
| 一个文件一个咒语 | 最小实现，可扩展 |

**这些限制不是遗漏，是语料边界。** 原文没写的东西，编译器不猜。
