# 规划书

**定位：B —— 一门魔法语言。**
读者照着文档能写咒语，编译器给出可预期的行为。

本文不写百分比。每个阶段用**可检验的验收判据**，并标明阻塞来自工程还是语料。

---

## 0. 什么叫「可用」

三条同时满足，才算这门语言成立：

1. 读者照 `docs/language.md` 写一个**文档里没出现过**的咒语，能编译通过；
2. 编译器输出与文档描述**逐字一致**（由 golden 测试锁定）；
3. 语义求值能**区分结构不同**的咒语，而不只是回显名字。

第 3 条是当前最大的缺口：`evaluate()` 只读 `element` 和 `kind`，IR 里的结构没人消费。

---

## 1. 现状基线（实测）

| 项 | 现状 |
|---|---|
| 语法 | `名字 : 元素 = 魔文 -> 魔文`，ASCII 符号 |
| 解析 | 正则逐行，单咒语/文件 |
| 诊断 | 容量 4 码 + 元素 6 码 |
| IR | `kind / element / create / emit`，两个 kind |
| 求值 | `Value(element, form)`，不消费结构 |
| 测试 | 38 个，含 golden 与文档防漂移 |
| 检查 | `ruff` / `mypy --strict` 全绿 |
| 可编译咒语 | **1.5 / 25**（光射线完整，丢冰块 create 未知） |

---

## 2. 结构性约束：语料供给

这是 B 的天花板，不是工程问题。

```
25 个咒语
├─ 1  完整环内结构（光射线）
├─ 2  有魔文总数、无结构（闪光术、丢冰块）
├─ 10 只有环数（闪光术、强光术、分散冰刺…）
└─ 12 连环数都没有
```

**语言能「编译到结构」的咒语上限 ≈ 3 个。** 超过这个数，编译器只能输出 `generic`，那不是编译，是回显。

所以本规划的所有阶段，都必须接受一个前提：**这门语言覆盖的是「有结构描述的少数咒语」，不是「原作的全部魔法」。**

---

## 3. 阶段

### M0 语言核心 —— 已完成

| 项 | 内容 |
|---|---|
| 目标 | 语法 → 解析 → 诊断 → IR → 求值骨架跑通 |
| 交付 | `lang.py` / `compile.py` / `examples/compile.py` |
| 验收 | 3 个 `.rune` 样例按文档输出；`test_docs.py` 防漂移；golden 锁输出 |
| 阻塞 | 无 |
| 翻案 | 若语法符号再变，`test_docs.py` 会先红 |

### M1 语义最小可用

| 项 | 内容 |
|---|---|
| 目标 | 让求值真的消费结构 |
| 交付 | `IR` 改为 `Apply(emit, create)`；`Value` 增加 `work`（魔文数） |
| 验收 | `光射线` 与 `闪光术` 的求值结果不同，且差异可追溯到「有无 emit」 |
| 阻塞 | **无**（纯实现） |
| 风险 | 仍只有 1.5 个样本，属于单点自证 |
| 翻案 | 若 `work` 只能取魔文数，则不引入任何新度量 |

**这是唯一一个「不依赖新语料」就能做扎实的阶段。** 建议先做完。

### M2 判定与等价

| 项 | 内容 |
|---|---|
| 目标 | 判断两个咒语是否功能等价 |
| 交付 | 规范形（模 C_n 旋转）+ 退化规则（`duty=0`、`ω=0`） |
| 验收 | `前 + 3×90° + 稍弱转动` 与 `后` 判定等价 |
| 阻塞 | **语料**：`后` 的两个魔文内容原文未给，「原本两个魔文」没说具体是哪两个 |
| 风险 | 若无法构造这对等价，M2 只能做「同源咒语」的平凡等价 |
| 退出 | 找不到第二个等价对 → 判定层降级为「只判结构相等」，不判语义等价 |

**M2 是本规划的分水岭。** 它能成立，这门语言才算有「优化」；它不成立，语言退化为翻译器。

### M3 多环

| 项 | 内容 |
|---|---|
| 目标 | 支持二环：内环产出信号，外环调制 |
| 交付 | 环嵌套语法；逐环容量 `C_in / C_out` |
| 验收 | 能表达五彩光球的结构 |
| 阻塞 | **语料**：内环数 7 出自疑问句；外环魔文数未知；染色魔文名未知 |
| 风险 | 只有 1 个样本，且样本本身不完整 |
| 退出 | 若无法确定外环结构，二环只做「环数声明」，不做语义 |

### M4 工具链

| 项 | 内容 |
|---|---|
| 目标 | 反编译：从语料生成 `.rune` |
| 交付 | `tools/decompile.py`，3 个完整咒语可往返 |
| 验收 | 生成 → 编译 → 与原 IR 一致（往返测试） |
| 阻塞 | 无（工程），但价值取决于 M2 |
| 翻案 | 若往返只能覆盖 1 个咒语，工具价值不足以支撑 |

---

## 4. 天花板

| 层次 | 内容 | 判定 |
|---|---|---|
| 必达 | M0 + M1：语法、诊断、结构消费 | ✅ 不依赖新语料 |
| 条件可达 | M2 + M3：等价判定、二环 | ⚠️ 取决于能否补上关键结构 |
| 不可达 | 覆盖全部 25 个咒语的语义 | ❌ 原文未给，任何工程都补不出 |

**「不可达」不是失败，是边界。** 规划书的价值之一，就是提前把这条线画出来，而不是做到一半才发现。

---

## 5. 退出条件

出现以下任一情况，说明定位 B 不成立，应转 A（审计报告）或 C（交互式百科）：

1. M1 做完后，`Value` 仍无法区分任何两个咒语（说明结构本身不承载信息）；
2. M2 找不到第二个等价对，且判定无法脱离单点；
3. M3 的二环语法只能靠猜，无法用文本验证；
4. 读者照文档写的「新咒语」总是落进 `generic`（说明语言没有覆盖力）。

第 4 条是最实际的检验：**如果读者写什么都变 generic，那这门语言就没有存在意义。**

---

## 6. 明确不做的事

| 不做 | 原因 |
|---|---|
| 覆盖全部 25 个咒语 | 原文无结构，做了也是编 |
| 把推断写成原文 | 破坏四分类，等于自欺 |
| 加入无文本支撑的检查 | 每加一条都要能指出依据 |
| 用百分比汇报进度 | 分母不存在 |
| 把「单点自证」包装成「语言推进」 | 这是本项目最容易犯的错 |

---

## 7. 建议的执行顺序

1. **M1**（纯实现，1 轮）——把 `evaluate` 做真，`Value` 带上 `work`。
2. **M4 的往返测试**（纯工程）——用现有 1.5 个咒语验证管线闭合。
3. **M2 的可行性探测**——先回答「`后` 的两个魔文能不能确定」。不能，就停在这里，转 A。
4. M3 视 M2 结果决定是否启动。

**先做能做的，再探测不能做的，最后才决定要不要继续。** 顺序反了，就会在假设上盖楼。
